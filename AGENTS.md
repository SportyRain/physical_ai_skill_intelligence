# Repository workflow

Before substantial work, read [PROJECT_START_HERE.md](PROJECT_START_HERE.md) and
follow the authoritative verification/status/history documents referenced there.

Always synchronize context with the latest authoritative `main` before reasoning
from project state. Follow the Start Here dirty-worktree and remote-freshness
rules; preserve existing work.

Do not restart prior project reasoning or silently override established
verification claims, DO_NOT_REIMPLEMENT boundaries, or rejected approaches.

When a milestone closes, a gate materially changes, or an important project
decision occurs, update `docs/PROJECT_HISTORY.md`.

`VERIFICATION_REPORT.txt` remains the authoritative verification claim ledger.
Do not silently upgrade UNKNOWN / UNRESOLVED / NOT_VERIFIED claims.

For live Ubuntu/UR3 work that this agent cannot execute directly, provide the
user exact commands and required observations, then continue from returned real
evidence instead of terminating solely because live access is unavailable.
